Overall verdict

Sound agent architecture, not yet production-ready by the framework's own bar — though closer than the first pass showed. Versioning (AgentCore Runtime + Bedrock Prompt Management) and end-to-end tracing (AgentCore Observability) turn out to already be covered at the platform level. What's still open clusters in three places: hard guardrail enforcement in front of the claim-registration action, PII handling before the LLM call, and a testing/eval loop. One Foundation item is now fixed in code (see the changelog below); read the rest as the pre-production punch list.

Since the last review · 2026-08-31

Confirmed with the team that agent/prompt versioning and observability are already handled by AWS-native tooling rather than missing — three topics below were re-scored accordingly. One Foundation gap was also closed in code this pass:

  • G1.22Added a runtime grounding gate (_GroundingGateTool in strands_agent.py, the equivalent inline wrapper in bot.py) — any tool argument whose field name was already returned by an earlier successful tool call this session must match that returned value, or the call is blocked before it fires. Topic detail

T1

Agent Orchestration

Partial

The core architectural calls are correct: one agent, one bounded conversational responsibility, and the "agent with a reasoning engine" tier is genuinely earned by real-time barge-in and dynamic tool choice rather than assumed by default. What's missing is the surrounding discipline the framework expects around that agent once it's live.

Aligned

  • G1.14A live, interruptible voice call with model-decided tool selection is a textbook Tier 3 case — correctly not forced into a scripted flow (see the module docstring in bot.py:11-22).
  • G1.07Start Small — one agent, three tools, no premature decomposition into Manager/Specialist agents the workflow doesn't need.
  • G1.05Agent versioning is handled at the platform level — each deploy is a distinct AgentCore Runtime version (create-agent-runtime / update-agent-runtime), and the prompt text is versioned separately in Bedrock Prompt Management. Rollback is repointing at a prior runtime ARN / prompt version, not reconstructing state from memory.
  • G1.22 (partial)The claim-registration tool can no longer fire on an invented or unverified argument — see the grounding gate added to bot.py / strands_agent.py in the changelog above.

Gaps

  • FoundationG1.04No fallback model or documented selection rationale — a Nova Sonic outage in the configured region halts Ava entirely.
  • FoundationG1.22The new grounding gate stops an invented identifier from reaching the tool, but there's still no business-rule gate (e.g. a claim-amount threshold routing to human approval) before the action executes.
  • FoundationG1.19No idempotency key on the claim tool call — a retried invocation (dropped ack, session rotation mid-call) could plausibly double-submit a claim.
T2

MCP & Tool Design

Partial

The dynamic tool-loading pattern is a genuine strength — nothing about a tool's name, schema, or description is hardcoded on either entry point, so the gateway can reshape its tools without a code change here. That same openness is also where the gaps live: nothing classifies which tools are safe to auto-invoke, and nothing treats what the gateway sends back as anything other than trusted.

Aligned

  • G2.15Minimum necessary toolset — exactly three tools (lookup, register claim, escalate), well inside any context budget.
  • G2.06Tool descriptions are read live from the gateway rather than redeclared, so behaviour can't drift from the source of truth (bot.py:129-190, strands_agent.py:193-212).
  • G2.09Generic session_id injection by schema inspection, not by hardcoded tool name — a well-scoped, minimal deterministic override on top of an otherwise fully agentic flow.
  • G2.11 (partial)_GroundingGateTool (strands_agent.py) and its bot.py equivalent now block a tool call whose arguments weren't actually returned by an earlier tool this session — detected generically by field name, not a hardcoded tool list, matching this file's existing "detect by schema, not by name" pattern.

Gaps

  • FoundationG2.11No info/action classification or per-tool autonomy level (auto / human-approve / escalate) — the claim-registration tool still runs unattended once its arguments pass the grounding check above; there's no threshold that routes it to a human.
  • FoundationG2.18Tool results are JSON-parsed and handed straight into the model's context (bot.py:165-172) with no delimiting as untrusted data — a compromised or malformed gateway response has a direct path to influencing Ava's next decision.
  • FoundationG2.19AWS credentials are read from .env / long-lived access keys rather than short-lived, task-scoped credentials from a secrets manager.
T3

Memory & Context

Partial

There's effectively no persistent memory here, and for this scope that's the right call — nothing about the workflow needs state to survive past the call. The one real exposure is what does flow through the single-session context: caller PII, unredacted.

Aligned

  • G3.23Clean per-call isolation — strands_agent.py builds a fresh BidiAgent and gateway connection per WebSocket, so concurrent callers never share state.
  • G3.04Need-justified memory — no speculative "log everything" store; session state is limited to the live conversation and a per-call session id.

Gaps

  • FoundationG3.25Mobile numbers, policy IDs, and vehicle registrations reach Nova Sonic's context unredacted — nothing minimises or tokenises sensitive fields before they enter the model (shared root cause with T4 · G4.16).
T4

Guardrails & HITL

Gap

This is the widest gap in the review, and the framework treats nearly all of it as Foundation-level. Every behavioural boundary Ava has — never fabricate, always confirm a number back, escalate when frustrated — lives entirely inside SYSTEM_INSTRUCTION. None of it is backed by a layer the model can't reason its way around.

Aligned

  • G4.23AI disclosure is explicit and up front — Ava states "I'm Ava, your AI Assistant" as her first sentence, not a dismissible banner (SYSTEM_INSTRUCTION, both files).
  • G1.02-adjacent judgment: the digit-by-digit read-back-and-confirm pattern before any lookup is a deliberate, well-specified control, even though it's enforced by instruction rather than code.
  • G4.10 (partial)The new grounding gate is a concrete instance of G4.10's "the model cannot reason its way around it" bar: the id-provenance rule now lives in an external wrapper the model never sees, not in the prompt it can drift away from.

Gaps

  • FoundationG4.02 / G4.10The identifier-provenance rule is now enforced (see Aligned, above); every other rule — "never fabricate," the escalation judgment, tone — is still prose the model is asked to follow, not a machine-evaluable check.
  • FoundationG4.19No risk/reversibility-based HITL trigger — claim registration is an irreversible business action gated only by Ava's own confidence, not a documented threshold.
  • FoundationG4.16No PII redaction before the LLM call — see T3 · G3.25.
  • FoundationG4.13No indirect-injection defence on gateway tool output before it re-enters the conversation.
  • AdvancedG4.26Logging exists (loguru / print tool-call traces) but isn't a structured, immutable audit record — good for local debugging, not for demonstrating compliance.
T5

Prompt Lifecycle

Partial

Versioning itself is well covered: the prompt is a git-tracked artefact and versioned in Bedrock Prompt Management. The residual risk isn't "no versioning" — it's that the code carries its own hardcoded copy of the instruction text rather than resolving it from Prompt Management at runtime, and that copy has quietly diverged into two places. Nothing yet checks that a prompt edit didn't regress behaviour, either.

Aligned

  • G5.13Versioned in two places: git history for bot.py / strands_agent.py, and separately in Bedrock Prompt Management — not a config-screen edit with no diff trail.
  • G5.04 / G5.26Clear role framing and an explicit scope-limitation instruction ("never fabricate... ask a clarifying question").

Gaps

  • AdvancedG5.13 / G5.17Two sources of truth for the same text: the git-committed SYSTEM_INSTRUCTION string (duplicated verbatim across bot.py and strands_agent.py) and whatever's live in Bedrock Prompt Management. Worth having the code resolve the prompt from Prompt Management at runtime instead of carrying its own copy, so there's one source and the two entry points can't drift from each other or from what's "deployed."
  • FoundationG5.22No evaluation dataset and no regression gate — a prompt change ships the moment it "sounds right" in a manual test, with no golden-case check (ties directly into T8).
T6

Knowledge Pipelines

Not applicable

This topic governs RAG corpora — ingestion, chunking, embedding, retrieval ranking. Ava has none: policy and claims data are read live from the AgentCore Gateway's backend systems of record, not from a document index this project owns. Nothing here to score against Topic 6 unless a knowledge base is added later (e.g. for general insurance FAQs).

T7

AIOps

Partial

Tracing was the biggest single item here, and it's already handled — AgentCore Observability means end-to-end tracing doesn't need to be built from scratch in this repo. What's left is the cost/identity/registry layer the framework expects around it.

Aligned

  • G7.01AgentCore Observability (CloudWatch GenAI dashboards) gives auto-instrumented spans for model calls and tool calls via the bedrock_agentcore runtime's built-in OpenTelemetry tracing — end-to-end tracing without custom instrumentation in this repo.
  • G7.02-adjacent: the [tool call] / [tool result] log lines in both entry points give a readable decision-path seed on top of the platform tracing.
  • —Lambda CORS is now driven by ALLOWED_ORIGIN (defaults to * for local testing) — set it at deploy time instead of shipping a hardcoded wildcard.

Gaps

  • FoundationG7.04 / G7.05No per-invocation token/cost tracking and no budget alerting or kill switch — a runaway loop or adversarial input has no ceiling.
  • FoundationG7.08No agent registry — nothing records model version, prompt version, and connected tools as one queryable record.
  • FoundationG7.14 / G7.16Ava runs under a developer's IAM access key rather than a distinct, scoped non-human identity with rotated credentials.
T8

Testing & Validation

Gap

There is no test suite of any kind in this repository today — no golden dataset, no automated scoring, no CI gate. Every item in this topic is currently unmet, and most of them are Foundation-level.

Gaps

  • FoundationG8.05No golden dataset for Ava's core judgments (identity confirmation, policy lookup, claim intake, escalation) — nothing to score a prompt change against.
  • FoundationG8.15 / G8.17No CI-gated regression run — a prompt or model-config change reaches main with no automated check.
  • AdvancedG8.09No adversarial test cases (prompt injection via a caller's speech, out-of-scope requests, boundary claim amounts).
